# 跨實例群組綁定協議 v1

## 範圍與授權

僅支持 HTTPS 根域名上的兩個獨立 EdgeChat 實例。公開、私有和 general 系統群可綁定，DM 不可綁定。每群最多一個未撤銷的綁定（邀請/待確認也佔位）。只有本站管理員可操作，服務端重新讀取管理員狀態並通過群管理授權。不會創建遠端可登錄賬號。

1. A 選擇群生成 10 分鐘有效的一次性邀請；邀請包含隨機綁定 ID、實例 UUID、HTTPS origin、群摘要和 256 bit 隨機 bootstrap 憑據。
2. B 管理員粘貼邀請、核對對方地址、選擇本群並明確同意導出未來純文字；B 生成獨立的 256 bit 長期綁定憑據，經 bootstrap 簽名的 HTTPS 認領提交給 A。兩端分別加密保存，過期邀請不能簽署後續消息。
3. A 核對 B 的實例 origin 和群摘要，再最終確認。激活通過持久化控制任務發送；B 驗證簽名並激活後返回簽名確認，A 驗證確認後激活。確認丟失時重複激活無副作用。

邀請屬於秘密，只展示一次；不要放在 URL、日誌或提交中。每綁定憑據使用各自本站加密密鑰加密保存（用途 AAD 綁定 binding ID），雙方不交換本站主密鑰。實例 UUID 持久化，origin 在首次使用時確定；域名遷移需解綁重建。

## 消息與控制

端點為 `POST /api/integrations/instance-bridge/v1`，JSON 信封包含 `v/type/bindingId/from/to/sentAt/nonce/data`。HMAC-SHA256 覆蓋原始請求正文，驗證簽名後再使用任何地址/群信息。響應簽名覆蓋請求 nonce、HTTP 狀態和原始響應正文，避免中間代理的假成功造成消息丟失。每次嘗試生成新的時間戳與 nonce，接受時鐘偏差 5 分鐘。穩定事件 ID 負責業務冪等；控制 revision 單調遞增，舊控制不可覆蓋新狀態；認領只能匹配第一次認領。重複已認證請求允許返回相同語義確認，不重複執行。

出站地址僅允許 HTTPS 443 根 origin，無用戶信息、路徑、query、fragment；拒絕 IP、localhost、內網/特殊域後綴，發送前核對公共 DNS A/AAAA 地址；禁止重定向。請求籤名綁定雙方 origin/實例/群/綁定。僅首次認領經 HTTPS 交換長期憑據，後續請求只發送簽名，不發送憑據。部署邊界為啟用 `global_fetch_strictly_public` 的 Cloudflare Workers 公網 fetch，不支持私網連接/隧道訪問。管理員需自行信任對方運營者：收到文字的對方可以保存或另行分享。

僅 `sender_kind=local AND source=edgechat` 的無附件新消息進入跨實例 outbox；Telegram 出站也使用同一原創條件。正文可以是 Markdown，接收端沿用安全渲染。回覆只發送新正文，不發送引用、提及權限或遠端 ID；附件及附件說明整條跳過。編輯/撤回不跨站傳播，已送達副本不會隨本站刪除消失。

## 一致性、暫停和重試

- D1 AFTER INSERT 觸發器與消息同事務登記 outbox，包含穩定事件 ID、加密正文快照和暱稱；失敗不會存在“消息成功但永久丟任務”的窗口。
- 每綁定最多 1000 條積壓，超限只累計可見的丟棄計數，不阻塞本站聊天。消息投遞最長 24 小時，失敗指數退避（30 秒起、最多 1 小時），單次網絡超時 10 秒，單輪最多 10 條。
- Durable Object alarm 僅在有任務時運行；每 15 分鐘一次全局索引查詢救援漏掉的喚醒，並執行有界過期清理，不按閒置綁定輪詢。DB 隊列是事實源，alarm 不是唯一登記。
- 請求啟動前通過原子條件更新領取任務；領取是“投遞已啟動”的線性化點。暫停/解綁後不再領取新消息，已領取/在途請求可能已送達。接收落庫仍由 D1 觸發器檢查綁定資格，不能用先查後寫繞過暫停。
- 暫停立即停止本端收發，清空本端消息積壓，持久化通知對方。對方獲知後也清空積壓。雙方各有獨立暫停開關，只有雙方均恢復才同步；目標 revision 是接收世代，恢復會變更世代，不依賴對方時鐘判斷暫停邊界。outbox 捕獲的舊目標世代不得在恢復後補發。
- 解綁本地立即撤銷資格並取消積壓；保留最小憑據墓碑最多 7 天用於重試解綁通知，最終清除。對方離線時無法保證立即獲知，但不能向本端繼續落庫。
- 接收消息和 receipt 同事務寫入；receipt 不引用消息行，軟刪、GC 硬刪後仍去重。receipt 保留到事件創建 48 小時後，而協議不接受超過 24 小時的事件。綁定撤銷或刪除後舊憑據不能導入；群組刪除原子撤銷綁定並登記解綁通知。
- 失敗狀態區分網絡/超時、鑑權/協議錯誤、遠端暫停/解綁、積壓滿和過期。管理員“重試”僅提前喚醒尚未過期的任務，不能復活已取消/過期消息。

## 發佈與恢復

增量遷移先於 Worker 發佈，舊代碼可忽略新增表/列/觸發器；沒有綁定時不導出任何舊消息。新安裝使用同一 schema 與遷移 manifest。新增 `INSTANCE_BRIDGE` SQLite Durable Object（migration v3），保留既有 DO 類。普通更新不覆蓋密鑰環。前端 demo 只模擬操作，不發送跨站流量。回退舊 Worker 前應暫停所有綁定；保留數據庫與密鑰，不執行破壞性回滾。

Telegram 仍使用原有盡力轉發機制，本次僅統一原創消息門禁；新 outbox 不冒充 Telegram 的持久化重試能力。跨實例投遞提供接收去重，但不承諾消息按來源發送順序到達。控制通知最終一致，後臺“控制操作發送中”表示遠端尚未確認。WAF/Access 必須允許協議路徑的已簽名公網請求，不能要求對端攜帶本站用戶 session。
