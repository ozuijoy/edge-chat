# 跨实例群组绑定协议 v1

## 范围与授权

仅支持 HTTPS 根域名上的两个独立 EdgeChat 实例。公开、私有和 general 系统群可绑定，DM 不可绑定。每群最多一个未撤销的绑定（邀请/待确认也占位）。只有本站管理员可操作，服务端重新读取管理员状态并通过群管理授权。不会创建远端可登录账号。

1. A 选择群生成 10 分钟有效的一次性邀请；邀请包含随机绑定 ID、实例 UUID、HTTPS origin、群摘要和 256 bit 随机 bootstrap 凭据。
2. B 管理员粘贴邀请、核对对方地址、选择本群并明确同意导出未来纯文字；B 生成独立的 256 bit 长期绑定凭据，经 bootstrap 签名的 HTTPS 认领提交给 A。两端分别加密保存，过期邀请不能签署后续消息。
3. A 核对 B 的实例 origin 和群摘要，再最终确认。激活通过持久化控制任务发送；B 验证签名并激活后返回签名确认，A 验证确认后激活。确认丢失时重复激活无副作用。

邀请属于秘密，只展示一次；不要放在 URL、日志或提交中。每绑定凭据使用各自本站加密密钥加密保存（用途 AAD 绑定 binding ID），双方不交换本站主密钥。实例 UUID 持久化，origin 在首次使用时确定；域名迁移需解绑重建。

## 消息与控制

端点为 `POST /api/integrations/instance-bridge/v1`，JSON 信封包含 `v/type/bindingId/from/to/sentAt/nonce/data`。HMAC-SHA256 覆盖原始请求正文，验证签名后再使用任何地址/群信息。响应签名覆盖请求 nonce、HTTP 状态和原始响应正文，避免中间代理的假成功造成消息丢失。每次尝试生成新的时间戳与 nonce，接受时钟偏差 5 分钟。稳定事件 ID 负责业务幂等；控制 revision 单调递增，旧控制不可覆盖新状态；认领只能匹配第一次认领。重复已认证请求允许返回相同语义确认，不重复执行。

出站地址仅允许 HTTPS 443 根 origin，无用户信息、路径、query、fragment；拒绝 IP、localhost、内网/特殊域后缀，发送前核对公共 DNS A/AAAA 地址；禁止重定向。请求签名绑定双方 origin/实例/群/绑定。仅首次认领经 HTTPS 交换长期凭据，后续请求只发送签名，不发送凭据。部署边界为启用 `global_fetch_strictly_public` 的 Cloudflare Workers 公网 fetch，不支持私网连接/隧道访问。管理员需自行信任对方运营者：收到文字的对方可以保存或另行分享。

仅 `sender_kind=local AND source=edgechat` 的无附件新消息进入跨实例 outbox；Telegram 出站也使用同一原创条件。正文可以是 Markdown，接收端沿用安全渲染。回复只发送新正文，不发送引用、提及权限或远端 ID；附件及附件说明整条跳过。编辑/撤回不跨站传播，已送达副本不会随本站删除消失。

## 一致性、暂停和重试

- D1 AFTER INSERT 触发器与消息同事务登记 outbox，包含稳定事件 ID、加密正文快照和昵称；失败不会存在“消息成功但永久丢任务”的窗口。
- 每绑定最多 1000 条积压，超限只累计可见的丢弃计数，不阻塞本站聊天。消息投递最长 24 小时，失败指数退避（30 秒起、最多 1 小时），单次网络超时 10 秒，单轮最多 10 条。
- Durable Object alarm 仅在有任务时运行；每 15 分钟一次全局索引查询救援漏掉的唤醒，并执行有界过期清理，不按闲置绑定轮询。DB 队列是事实源，alarm 不是唯一登记。
- 请求启动前通过原子条件更新领取任务；领取是“投递已启动”的线性化点。暂停/解绑后不再领取新消息，已领取/在途请求可能已送达。接收落库仍由 D1 触发器检查绑定资格，不能用先查后写绕过暂停。
- 暂停立即停止本端收发，清空本端消息积压，持久化通知对方。对方获知后也清空积压。双方各有独立暂停开关，只有双方均恢复才同步；目标 revision 是接收世代，恢复会变更世代，不依赖对方时钟判断暂停边界。outbox 捕获的旧目标世代不得在恢复后补发。
- 解绑本地立即撤销资格并取消积压；保留最小凭据墓碑最多 7 天用于重试解绑通知，最终清除。对方离线时无法保证立即获知，但不能向本端继续落库。
- 接收消息和 receipt 同事务写入；receipt 不引用消息行，软删、GC 硬删后仍去重。receipt 保留到事件创建 48 小时后，而协议不接受超过 24 小时的事件。绑定撤销或删除后旧凭据不能导入；群组删除原子撤销绑定并登记解绑通知。
- 失败状态区分网络/超时、鉴权/协议错误、远端暂停/解绑、积压满和过期。管理员“重试”仅提前唤醒尚未过期的任务，不能复活已取消/过期消息。

## 发布与恢复

增量迁移先于 Worker 发布，旧代码可忽略新增表/列/触发器；没有绑定时不导出任何旧消息。新安装使用同一 schema 与迁移 manifest。新增 `INSTANCE_BRIDGE` SQLite Durable Object（migration v3），保留既有 DO 类。普通更新不覆盖密钥环。前端 demo 只模拟操作，不发送跨站流量。回退旧 Worker 前应暂停所有绑定；保留数据库与密钥，不执行破坏性回滚。

Telegram 仍使用原有尽力转发机制，本次仅统一原创消息门禁；新 outbox 不冒充 Telegram 的持久化重试能力。跨实例投递提供接收去重，但不承诺消息按来源发送顺序到达。控制通知最终一致，后台“控制操作发送中”表示远端尚未确认。WAF/Access 必须允许协议路径的已签名公网请求，不能要求对端携带本站用户 session。
