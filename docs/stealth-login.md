# 隐身登录页的实例级外观

隐身模式首次初始化设置时，为实例生成一套登录页组合，保存在 D1 的
`site_settings.stealth_mode.appearance` 中。已有隐身设置会在首次读取时自动补齐。
重新部署、刷新页面、登录失败或切换隐身开关不会重新生成组合；无需新增数据库迁移。
并发初始化和旧设置升级以数据库中的结果为准，避免多个请求各自显示不同的页面。

只组合非功能特征：

| 模块 | 变化 |
| --- | --- |
| 页面容器 | 简洁主区域、带边框区块、独立面板 |
| 标题 | 直接标题、分隔标题、带内部文字容器的标题 |
| 字段排版 | 嵌套标签、独立标签、显式关联标签与反向布局 |
| 提交区域 | 直接按钮、靠右按钮、页脚按钮 |
| 失败提示 | 段落、区块、辅助区域；都保留 `role="alert"` |
| 外观 | 配色、系统字体、圆角、间距、宽度、上边距 |
| 非功能标识 | 表单控件 ID、常见 CSS 类名、样式规则顺序 |
| 通用文案 | 标题、按钮和失败提示的普通登录措辞 |

只输出选中的模板，不向页面嵌入整个模板库、配置版本、模板序号或随机种子。
页面不包含脚本、品牌资源、远程字体或第三方请求。所有模板保留显式或嵌套的
字段标签、自动填充、键盘提交、焦点标识及小屏适配。

账号与密码字段、长度限制、提交编码、登录路由、会话 Cookie、来源校验、
CSP 和资源认证行为维持原有协议。错误账号、错误密码与封禁账号在同一实例
返回同一种通用错误，模板选择不依赖账号、密码或认证结果。

这是减少固定页面指纹的措施，并不保证无法归一化识别，也不能保证误封成本。
有限模板仍可以被枚举；表单协议、HTTP 行为和服务基础设施仍可能提供共同特征。
修改功能协议或认证流程不属于这次外观随机化的范围。
